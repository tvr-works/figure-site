## Positioning

Working internal statement:

> A trade calculator designed around the calculation: mode-specific keys, responsive diagrams and related results, with construction, sheet metal and HVAC calculations together on iPhone at an accessible one-time price.

The intended order of persuasion is useful capability, an understandable native workflow, then ownership and price. Accessibility of price is an owner value. Long-term maintenance and commercial viability also matter.

The main audience is tradespeople and apprentices who need dimensional and geometric calculations at work. Experienced handheld users need evidence of capability; newcomers need to understand how they will use it. The demonstration should answer both.

The code supports mode-specific key definitions and geometry that fits the entered dimensions and highlights selected results. No usability study currently establishes superiority or an absolute reduction in learning time. Demonstrate the behaviour instead of describing the whole app as intuitive.

## The three proof sequences

Each proof has one headline and one short description. The stage uses real app content. Adaptive keys follows the owner-requested repeating input loop below; the other proofs retain their existing short-sequence proposals.

### Adaptive calculations

Headline:

> Build your calculation.

Description:

> Choose a mode, enter a measurement, and tap what it represents.

One upright iPhone remains anchored while its screen repeats a three-step timeline: **Select mode → Enter measurement → Assign**. For each mode, select it from the native launcher, enter 12 Inch, tap the appropriate input key, hold the assignment, then use Close and the launcher before the next mode. Do not add another input, Equals or a full result tour to this proof.

Cycle Right, Oblique, Circle, Cylinder, Cone, Ratios, Offset, Roof and Stairs. Use a dimensional input appropriate to each: Run, a, Diameter, A, Length or Rise. Cone uses the real 2nd/Cylinder action; Ratios supports a dimensional quantity. See the linked mode plan for the exact assignment per mode.

Retain the phone frame, correct aspect ratio, diagram/readout and complete keypad context. Keep the timeline labels stable and highlight the current action with short contextual values. Include Pause, Next mode and the current mode count. Loop only while this proof is active and visible. Respect manual pause, reduced motion and the need to inspect focused content. This owner-requested repeating input loop supersedes the earlier one-pass rule for Adaptive keys only.

Use actual captured app state and taps for production. The generated single-input frame is a composition study. Never imply that selecting a mode, assigning a value or cycling results are the same action. The change in keys follows mode selection; the current proof ends each pass after assignment.

### Visual results

Headline:

> See what each result measures.

Description:

> Change a dimension or cycle through results. The diagram updates and highlights the selected measurement.

Sequence:

1. Start with the real 3 ft by 4 ft triangle and a highlighted 5 ft diagonal.
2. Change an input and show the corresponding shape change using a newly captured, verified app example.
3. Cycle to an angle and show the selected arc and matching label.
4. Optionally use a captured roof or stair example to demonstrate a different figure without another full page section.

The proof is the relationship between input, geometry, result and highlight. A static decorative blueprint does not establish that relationship.

### Built-in Help

Headline:

> Help without losing your place.

Description:

> Bring up worked examples, explanations, and practical uses alongside your calculation. Return to your guide where you left off.

Demo timeline: **Find guidance → Try it → Resume reading**.

Open the native Help sheet over the current calculation. Find a relevant guide, show its plain-language concept explanation, diagram and worked steps, and briefly reveal its practical applications. Dismiss Help, use the retained calculation, then reopen the same article at the saved reading position. Hold that final state long enough to make continuity visible.

Prefer a guide such as Find rise and run from a slant, whose Which function? and Also useful for sections explain a mathematical relationship and its use in framing, sloping pipe/duct and ramp layouts. Capture a calculation compatible with that example. See [Help proof specification](HELP-PROOF.md) for the sequence and inspected evidence.

Help retains its article, search and reading position within the current calculator session. Do not claim cross-restart restoration. Use the actual More → Help path; do not invent contextual topic selection or a persistent native Help tab.

Recent Values remains a useful supporting capability in the inventory. It no longer shares the third proof's main narrative. Do not describe Help as unnecessary or imply that users ought to know the math already.

## Calculation range

Headline:

> Construction, sheet metal, and HVAC in one calculator.

Description:

> Work with roofs, stairs, duct offsets, geometry, and unit conversions.

Sequence:

Use a short, explicitly labelled set of example stages, with job names always visible: Duct offset, Stair layout, Unit conversion. The first useful still can be Duct offset, since the result family demonstrates specialist depth.

- Duct offset: length 10 ft, offset 5 ft and height 7 ft produce centerline radius 6 ft 3 in. Next result is wrapper length 11 ft 7⅛ in; later results include heel radius, throat radius and angle.
- Stair layout: 9 ft 11 in rise and 7½ in target riser produce 7 7/16 in risers. The setup also uses 10 in treads, 80 in headroom and 10 in floor thickness. Further results include 16 risers, 15 treads and a required run of 12 ft 6 in.
- Unit conversion: 5 ft 7½ in becomes 5.625 ft. A second authored example converts 14 ft to 4.267 m or 4267.2 mm.

Keep a short visible capability line or native disclosure for the rest of the range: right and oblique triangles, circles/arcs/segments, cylinders/cones, roof rafters/hips/valleys/jacks, ratios, trigonometry and supported physical units. All calculations opens a grouped inventory; it must not become a second carousel.

Use Next example to move between jobs and Next result only when advancing a real native result sequence. Do not label skipped highlights as consecutive equals presses.

HVAC copy must describe implemented calculations and guides precisely. Do not imply equipment selection, load sizing or the exact dedicated controls of the reference handheld.

## Interaction rules

- Selecting a proof immediately displays its completed or otherwise meaningful still.
- Replay runs roughly 6–10 seconds and holds the useful ending.
- The proof tabs do not auto-advance. Adaptive keys repeats its input loop within its own active stage, with pause and reduced-motion handling.
- Optional Play overview gives a short tour across the three proofs, with Pause/Resume. Its length follows the readable content, not a forced claim about how quickly someone can learn the app.
- A manual proof-tab selection stops the previous proof. Next mode is an explicit local navigation action inside Adaptive keys; respect the current pause state.
- Pause when offscreen, the document is hidden, or focus enters a running sequence. Honour manual pause.
- Reduced motion uses final stills and explicit stage controls.
- Keep one playback state owner. Preserve the selected proof/stage when a visitor scrolls away and back.
- On mobile, show all three proof labels and keep the changing diagram/readout readable. Do not shrink a whole second phone below legibility.
- The hero remains visually stable; its phone render does not run a competing slideshow.
- Measurements shown outside the app capture are read-only example values, not simulated arbitrary-input form fields.
- Keep the proposition, capability summary, initial result and purchase action available without JavaScript.
- Captions and stills must work without sound or successful video playback.

## Pricing recommendation for discussion

Owner position: accessible pricing, no subscription, considering $4.99. A free release was considered but has not been selected.

Recommendation: evaluate **$9.99 USD once** as the standard launch price. Treat this as a pricing hypothesis, not an established optimum. It keeps the low-friction purchase principle while giving more room for ongoing iOS maintenance and support.

$4.99 once is also consistent with an access-first goal. At $4.99, roughly twice the purchases are needed to match the gross receipts of $9.99, before fees, taxes, refunds or acquisition costs. Nothing inspected establishes that the lower price would generate that increase.

Do not choose free as a response to a competitor's model unless the owner separately accepts the funding and support implications. Do not promise unlimited future features or lifetime service in purchase copy.

Avoid an invented temporary launch discount. If the owner chooses an introductory offer, record its real price, standard price and genuine terms separately.

The public homepage should show the actual approved price and No subscription. Do not use per-coffee framing, a fabricated higher crossed-out price or a general $100 comparison that confuses handheld and app pricing.

Price is unresolved. No App Store settings or public website have been changed by this storyboard.

## Agreed implementation stack

Use Vite, React, TypeScript, current stable Tailwind, and shadcn components built on Base UI. Astro is not part of this implementation.

Keep the hero, purchase information and existing policy/support routes in static HTML. React owns the three-proof interactive area and its playback state. Use the official Vite multi-page build, Tailwind Vite integration and shadcn Base UI component APIs. Pin installed versions in the package lockfile.

Preserve /support, /privacy and 404 behaviour. Vite changes the build/output from the existing exit-0/public setup to npm run build/dist; update deployment documentation without changing the hosted service. main remains the production branch. Keep noindex until public launch is explicitly requested.

Price and public App Store availability remain unresolved. Keep purchase content configurable. A local review can show the proposed price, but must clearly distinguish this from an available public purchase. Do not silently approve $9.99 or add a misleading live purchase destination.

One demo controller owns proof, mode, stage and playback. Use captured app screens and recordings rather than a second calculation engine. The content and actions remain understandable in text without animation or sound.
